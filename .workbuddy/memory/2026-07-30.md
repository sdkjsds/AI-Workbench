## 手机端滑动跨模块误跳修复（用户 11:48 反馈：公考滑动跳到经济、要首尾边界提示）
- 根因：`attachArticleSwipe` 每次打开文章都往同一个 `#view` 元素 `addEventListener` 新 touch 监听、旧的不移除。之前在 经济 打开过文章（监听器记着经济 ctx），退回再进 公考 打开，一滑动两个 handler 都触发 → 陈旧的经济 ctx 跟着翻，表现成"从公考跳到经济"。
- 改动（commit 7d2ce53，1 file）：
  1. `attachArticleSwipe(el)` 只挂一次（`el._swipeAttached` 标志），handler 内部**实时读** `state.articleContext`（永远是当前模块），根除累积误跳。
  2. `openArticle(it, moduleArg)` 新增显式 module 参数（renderFeedList 点击时传 module），不再只靠 `state.lastView` 推导，模块边界确定。
  3. 方向按用户心智模型：**左滑=上一条、右滑=下一条**（之前写反已纠正）。
  4. 边界：第一条左滑 → toast「这是第一条」不切换；最后一条右滑 → toast「这是最后一条」不切换。
  5. 加 `state.inArticle` 标志（openArticle 置 true、navigate 置 false），防止在总览/列表页滑动误触发文章跳转。
- 待用户 push + 手机硬刷 PWA。

## 刷新改为累积+回溯更旧页（用户 12:56 反馈：要拉更早的信息、不要"与上次相同"、保证每次有新东西）
- 旧逻辑：`refresh` 只取各源最新 10 条并**覆盖**存储 → 源不更新就"与上次内容相同"。
- 改动（commit fa77d49，4 files）：
  1. `rss.js`：`fetchModule(module,sources,opts)` 重构——`mapItem` 抽函数；支持 `startPage/pages` 分页（`?paged=N`，源不支持则返回相同内容由 seen 去重后 `added===0` 自动停翻）；每源单次取 `LATEST_PER_SOURCE=20`（扩大窗口）；不再截断到 10 条，按时间倒序返回全部。
  2. `storage.js`：新增 `getFeedMeta/saveFeedMeta`（分页游标 `feeds/<m>.meta.json` 记已拉到第几页）。
  3. `index.js` refresh 路由重写：先拉最新页合并进 `merged`(Map, 保留 read/saved) → 若顶部无新(`newFromLatest===0`)则按游标回溯 `paged=2..4` 拉更旧内容直到无新增 → 排序+容量上限 200 → 写回 → 返回 `{items, newCount}`（不再是纯数组）。
  4. 前端 `renderer.js` refreshFeed：改用 `data.items/newCount`；提示改为「已更新：新增 N 条（共 M 条）」/「已拉到最早的内容（共 M 条）」，**不再提示"与上次内容相同"**。
- 本地实测：gongkao 首刷累积 50 条；立刻二刷顶部无新→回溯拉到 2025-06-05 旧文，总条数 50→53 新增 3，达标。GET /api/feed/:m 仍返回数组（前端初载/总览不变）。
- 说明：源真正静止且不支持分页时仍无新内容，此时提示"已拉到最早"，属诚实情况；多数 WordPress 类源(paged)可不断回溯。待用户 push + 手机硬刷。
